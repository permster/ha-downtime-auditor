**Downtime Auditor 0.5.1** fixes interrupted-run detail on Home Assistant 2026.9 and makes the dashboard react as things happen.

## Fixed

- **Interrupted findings on Home Assistant 2026.9 and newer** now show which step a run stopped at and how far its delay or wait had got, as on older versions. Home Assistant 2026.9 changed how it stores automation traces; Downtime Auditor reads both layouts, so older versions keep working. The same detail is back on the dashboard's **Live status** tab.
- **Changing a severity label in Home Assistant's label editor** now updates the current report straight away, as the dashboard's rating selector already did. For example, rating an automation **None** removes its Repairs issue. Before, the change only applied from the next restart.
- **Timeline:** very frequent triggers (for example every 15 seconds) are drawn as one dashed line over the whole downtime, with a count, instead of a solid bar that seemed to stop halfway.
- **Mobile:** long entity IDs no longer run underneath a finding's tags.

## Improved

- **Right after a restart,** the dashboard says when the new report will be ready. It waits for the *startup settle delay* (90 s by default) so integrations can restore their real states first, and it updates by itself when the report arrives.
- **After updating the integration,** an open dashboard tells you it's running old code and offers a **Reload** button. Before, a page left open across an update could show counts with an empty findings list until you refreshed it.
- **Live status** updates the moment an automation or script starts or finishes, instead of every 10 seconds. It shows how long each run has been going and the step it's on. Most automations finish in milliseconds, so only ones in a `delay` or `wait` stay listed.
- A failed time condition now says what was required, for example "at 00:55 (allowed 02:55–06:55)", not just the time.
