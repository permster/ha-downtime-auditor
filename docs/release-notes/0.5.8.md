This release helps you act on a finding: what it would have changed, and a button to run it. It also reports states that a crash or power loss reverted.

## New

- **What it would have changed.** Missed and interrupted findings list the entities that the actions that didn't run would have changed, with their **live** state and whether it already looks right, for example *input_boolean.variable_night · turn_on → now off ⚠ expected on*. For a missed trigger, that's the actions that would have run (the matching `choose` option). For an interrupted run, it's the step it stopped at and everything after it.
- **Run actions now.** A button on the finding runs the automation's actions (or restarts the script) once, after a confirmation. Running by hand isn't the same as the missed trigger: there's no trigger data, and the time and states differ. The confirmation says so, and warns when the actions choose by trigger id, since they then probably won't take the same path. Check the states afterwards.
- **Reverted states.** After a crash or power loss, helpers and other entities that restore their state come back with Home Assistant's saved copy, which is written only every 15 minutes, so a change made just before is lost (an `input_boolean` switched on at 7:00:00 comes back off). Downtime Auditor now keeps their values itself, within a second of each change, and reports any that came back different as a new **Reverted** finding type: the value before and after, when the change was made, Home Assistant's older copy, the live value, the automations that use the entity, and a **Set back** button (after a confirmation). It has its own sensor (`sensor.downtime_auditor_reverted_states`), Repairs text and dashboard tile. A state that's already back when the report is made is None. By default it checks the restored entities that automations and scripts use; *Check for reverted states* in the options can check all of them, or turn it off.
