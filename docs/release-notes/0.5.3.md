**Downtime Auditor 0.5.3** fixes sun and zone triggers on Home Assistant 2026.9 and newer.

## Fixed

- **Sun triggers on Home Assistant 2026.9+** showed up as *"Could not analyse trigger: attribute name must be string, not 'NoneType'"* instead of being checked. Home Assistant 2026.9 changed how it stores sun and zone trigger settings. Downtime Auditor now reads both the old and new layouts, so a sunset or sunrise missed during a downtime is reported again (and nothing is reported when none was due).
- **Zone triggers on Home Assistant 2026.9+** could only say *"change detected but match could not be evaluated"*. They now check enter/leave as before.
- **A trigger Downtime Auditor can't analyze is no longer reported as a missed trigger.** That's a Downtime Auditor problem, not something that happened to your automation. These triggers are now listed once, under *Couldn't analyze* on the dashboard and in the notification. They never raise a Repairs issue, and Home Assistant's log gets a warning with the details, so you can report them.

## Changed

- US spelling throughout (*analyze*, not *analyse*). In the JSON report, `meta.analysed_at` is now `meta.analyzed_at`; older saved reports keep the old key.
