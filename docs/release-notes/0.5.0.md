**Downtime Auditor 0.5.0** tells you not just *what* a restart missed, but *how much it matters* and *whether it would even have run*.

> **Upgrading from 0.4?** The upgrade is automatic, but some entities and event keys changed. Read **Breaking changes** below before you update automations that use them. Downgrading to 0.4 afterwards isn't supported.

## New

- **Severity.** Rate any automation or script Critical / High / Medium / Low / None with the `downtime_auditor_sev:` labels, which are created for you on first start, or pick a rating from a finding on the dashboard. Unrated automations are Medium. Repairs, push and `needs_attention` only consider findings at or above a minimum severity you choose.
- **Condition checks.** For each missed trigger, the automation's conditions are checked at the time it should have fired (time, sun, state, numeric state, zone, template, trigger id, and/or/not). If they would have failed, the finding is rated None and hidden by default. After a real outage, state-based conditions use the values from just before the downtime; when only those decide the result, the finding is marked **"probably failed"** but stays visible, because something may have changed while Home Assistant was down. What-if windows use recorder history.
- **`sensor.downtime_auditor_highest_severity`**: `critical` / `high` / `medium` / `low` / `none`.
- **`downtime_auditor.create_severity_labels`** service, plus a button on the dashboard, to recreate any severity labels you deleted.
- **Dashboard:** severity badges and colors, a minimum-severity / confidence / "show None" filter bar, a rating selector and a condition breakdown on each finding, and a highest-severity column in History.

## Changed

- **Confidence** now reads Confirmed / Probable / Possible / Unknown, shown as a neutral 4-step meter instead of a red "high" tag. Severity is now the only colored attribute.
- **"Possibly missed" and "Unverifiable" are now Missed findings** with lower confidence (Possible / Unknown).
- **Repairs and push have a minimum severity.** Fresh installs default to High. **Upgraded installs are set to Medium**, so nothing goes quiet until you've labelled your automations and raised it.
- **"Fired at startup" findings are Low** unless the automation is rated Critical, so at the Medium threshold they no longer cause a push or a Repair on their own.
- **Critical is never downgraded.** A Critical automation with an event, webhook, MQTT, tag or conversation trigger raises a Repair after every restart, because a message could have been lost each time.

## Breaking changes

**Entities.** Entity IDs below are the defaults; if you renamed one, look for it by name.

| 0.4 | 0.5 |
|---|---|
| `sensor.downtime_auditor_possibly_missed_triggers` | **Removed.** These are now Missed findings with Possible confidence. |
| `sensor.downtime_auditor_unverifiable_triggers` | **Removed.** These are now Missed findings with Unknown confidence. |
| `sensor.downtime_auditor_fired_during_startup` | `sensor.downtime_auditor_fired_at_startup`, renamed in place, so its history and customizations are kept. The ID only changes if it was still the default; a custom ID stays. |
| — | `sensor.downtime_auditor_highest_severity` (new) |

- `sensor.downtime_auditor_interrupted_automations` and `sensor.downtime_auditor_missed_triggers` keep their IDs, but now count findings with severity Low or higher. **The Missed count is usually higher than before**, because former Possibly missed and Unverifiable findings are now included.
- **`binary_sensor.downtime_auditor_needs_attention`** used to be on for any interrupted, missed or possibly-missed finding. It's now on when a finding is at or above *Minimum severity for Repairs*. That's Medium after an upgrade, so it behaves as before until you raise it.
- Long-term statistics for the two removed sensors stay in the database until you delete them in **Developer tools → Statistics**.

**`downtime_auditor_report` event data**

- `counts` is keyed by `interrupted`, `missed`, `fired_at_startup`. `possibly_missed` and `unverifiable` are folded into `missed`; `fired_during_startup` is now `fired_at_startup`; `skipped` moved to its own key.
- New keys: `counts_by_severity`, `highest_severity`, `needs_attention`, `skipped`.
- **Deprecated:** `actionable` is still sent, but it now equals `needs_attention`, not the old interrupted + missed + possibly-missed count. It will be removed in 0.6.0, so switch to `needs_attention`.

**Options removed:** *Repairs for "possibly missed" too* and *List unverifiable triggers*. The minimum-severity options and the dashboard filters replace them; they're removed from your configuration automatically.

**History:** past downtimes are shown in the new terms and marked *v0.4*; their severity column shows "—". Files on disk are not rewritten.

## Fixed

- Disabled automations no longer appear in what-if results, and aren't reported after a restart when they were off before it.
- The dashboard remembers its tab, filters, open findings and what-if results when you open an automation's editor or traces and come back. Edit and Traces are now real links, so Ctrl/middle-click opens a new tab.
